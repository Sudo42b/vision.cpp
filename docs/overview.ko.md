# 개요

[English](overview.md)

_vision_.cpp 는 컴퓨터 비전 신경망을 실행하는 C++ 라이브러리다. GGUF 파일에서 가중치를 읽고,
[ggml](https://github.com/ggml-org/ggml) 로 계산 그래프를 만들어 CPU 나 GPU 에서 돌린다.
결과물은 네이티브 바이너리 하나다 — Python 도, 프레임워크 런타임도, 교환 포맷 해석기도 없다.

[llama.cpp](https://github.com/ggml-org/llama.cpp) 와 같은 발상을 언어 모델이 아니라 비전
모델에 적용한 것이다.

## 핵심 발상: 모델은 파일이 아니라 코드다

대부분의 추론 스택은 모델을 **데이터**로 다룬다. 그래프를 ONNX 나 TorchScript 로 export 하면,
범용 런타임이 그 그래프를 읽어 연산자를 커널 라이브러리에 매칭하고 해석해 실행한다. 이런 런타임은
누군가 export 할 수 있는 모든 연산자를 지원해야 해서 덩치가 크고, 시작할 때 그래프를 계획해야
해서 로딩이 오래 걸린다.

_vision_.cpp 는 모델을 둘로 쪼갠다.

| 구성 | 형태 | 있는 곳 |
| :--- | :--- | :--- |
| **구조** | ggml 그래프를 만드는 C++ | 바이너리에 컴파일됨 |
| **가중치** | GGUF 텐서 | 실행할 때 읽는 `.gguf` 파일 |

런타임에 그래프 기술(記述)을 해석하는 단계가 없다. **기술 자체가 없기 때문**이다 — 그래프는
이미 컴파일된 코드다. 배포물이 작고 시작이 빠른 이유가 이것이고, 이 프로젝트의 핵심 트레이드오프도
여기서 나온다. **아직 지원하지 않는 모델을 추가하려면 파일을 export 하는 게 아니라 코드를 쓰거나
생성해야 한다.**

가중치는 바깥에 남으므로 체크포인트 교체·정밀도 변경·양자화에는 재빌드가 필요 없다.

## 무엇을 얻는가

- **자기완결적.** 의존성은 ggml, 이미지 입출력용 `stb`, 선택적으로 `fmt` 뿐이다.
  런타임 경로에 Python 이 없다.
- **CPU 와 GPU.** CPU 는 어디서나 돌고, Vulkan 하나로 NVIDIA·AMD·Intel 을 함께 덮는다.
- **작고 빠르게 뜬다.** 배포 크기와 모델 로딩 시간이 이 프로젝트의 명시적 목표다 —
  현재 수치는 [Performance](../README.md#performance) 절 참조.
- **모듈식.** 내장 모델을 만드는 데 쓴 프리미티브가 그대로 공개돼 있어, 직접 조립할 수 있다.

## 어떻게 짜여 있나

라이브러리는 층으로 나뉘어 있다. 각 층은 따로 써도 되므로, 필요한 만큼만 내려가면 된다.

| 층 | 헤더 | 제공하는 것 |
| :--- | :--- | :--- |
| 모델 API | `visp/vision.h` | 완성된 모델 — 로드하고, 돌리고, 결과를 받는다. |
| 이미지 입출력 | `visp/image.h` | 로드·저장·리사이즈·타일링·변환. |
| 신경망 레이어 | `visp/nn.h` | `conv_2d`·`group_norm`·attention 등 구성 요소. |
| 그래프와 백엔드 | `visp/ml.h` | GGUF 로딩, 가중치 전송, 그래프 구성, 실행. |
| 검출 후처리 | `visp/postproc.h` | anchor·디코드·NMS·RoIAlign·마스크. |
| 추적 | `visp/tracker.h` | 프레임 간 ByteTrack 매칭. |

그 위에 프런트엔드가 둘 있다.

- **`vision-cli`** — 내장 모델용 커맨드라인 도구
  (`vision-cli sam -m MobileSAM-F16.gguf -i image.jpg -p 100 200 -o mask.png`).
- **Python 바인딩** — `bindings/python`. 스크립팅과 레퍼런스 구현 대조용.

## 모델을 넣는 방법

구조가 코드이므로, 모델을 추가하는 길은 둘이다.

**직접 쓴다.** [모델 구현 가이드](model-implementation-guide.md) 를 따른다. `nn.h` 프리미티브로
망을 기술하고, 원본 체크포인트를 GGUF 로 바꾸는 변환 스크립트를 함께 만든다. 내장 모델들이 이
방식으로 구현돼 있고, 레이아웃과 정밀도를 가장 세밀하게 통제할 수 있다.

**생성한다.** PyTorch→ggml 컴파일러가 traced 모듈에서 같은 형태의 C++ 를 뽑아낼 수 있다. 변종이
많은 모델 계열은 전부 손으로 쓰는 게 현실적이지 않으므로 이쪽이 실용적이다.
[MMDetection 가이드](mmdet-detectors.ko.md) 가 그 경로를 다룬다 — 생성된 코드가 지켜야 할
인터페이스, 그리고 trace 로 잡히지 않는 부분(데이터에 따라 흐름이 갈리는 검출 head)을 손으로 쓴
C++ 로 남기는 방법까지.

두 길은 결국 같은 곳에서 만난다. 그래프를 만드는 `<Arch>_forward` 함수 하나와, 가중치 GGUF 하나.

## 범위

_vision_.cpp 는 추론 라이브러리다. 학습도, autograd 도, optimizer 도 없다.

범용 모델 런타임도 아니다 — 임의의 export 된 그래프를 실행하는 것을 목표로 하지 않는다. 지원하는
모델은 구현했거나 생성한 것들뿐이고, 그래서 [README](../README.md#features) 의 모델 목록이
유한하며 그 목록을 늘리는 일이 곧 코드 변경이다.
